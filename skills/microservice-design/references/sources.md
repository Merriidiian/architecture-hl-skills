## Уточнения и дополнения

- Варианты DB-first/Kafka-first описаны как выбор под требования, а не обязательная последовательность развития всех систем.
- Разделение команд и запросов не обязано означать два сервиса и две БД. Outbox не превращает систему автоматически в event sourcing.
- «Ровно один эффект» ограничен спроектированной идемпотентной границей. Внешний платёжный API нуждается в собственном контракте; Inbox в локальной БД недостаточно.
- Пропуск плохого события в DLQ оценивается вместе с порядком и типом проекции. Для зависимых дельт это может разрушить инвариант.
- Одного Kafka key недостаточно при параллельных relay. Lease допускает запоздавшую отправку; токен защищает изменение состояния БД, но не отменяет уже отправленное сообщение.
- HTTP `409 projection_not_ready` и конкретная форма квитанции сохранены как пример OrderFlow, не как общий стандарт.
- Сервер может генерировать ID, если его выбор и квитанция устойчивы и согласованы с идемпотентностью. Обязательная клиентская генерация из учебного сценария обобщена.
- Межсервисный процесс, компенсации, совместимый rollout и восстановление добавлены как критерии завершённости проектного решения; это редакторские дополнения, а не дословные требования практикумов.

Для деталей PostgreSQL использованы первичные страницы: [изоляция транзакций](https://www.postgresql.org/docs/current/transaction-iso.html), [RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html), [ограничения](https://www.postgresql.org/docs/current/ddl-constraints.html). Реализацию нужно сверять с целевой версией.
