# Шаблон архитектурного решения для одной операции

Опиши одну команду или один запрос. Заполни строки, от которых зависит поведение этой операции. Для каждой гарантии укажи наблюдаемый результат.

| Что заполнить | Пример заполнения |
| --- | --- |
| Действие и владелец | Редактор публикует карточку. Контекст каталога владеет карточкой и проверяет, что она готова к публикации. |
| Вход и момент успеха | Gateway передаёт команду по gRPC. Владелец возвращает ID и новую версию после фиксации транзакции. |
| Асинхронная реакция | В той же транзакции записывается событие публикации в Outbox. После доставки через RabbitMQ подписчик обновляет поисковую проекцию. |
| Повтор и отказ | При повторной доставке того же события подписчик сохраняет один результат. Задержку доставки можно увидеть по возрасту записи Outbox. |
| Чтение и свежесть | Частые GET опубликованной карточки используют Redis. Ключ учитывает ID и область видимости. Событие сбрасывает запись, TTL ограничивает срок её жизни. |
| Файл, если есть | Каталог хранит ссылку на обложку. Загрузка и получение файла проходят через контракт `s3-storage`. |
| Проверка | Опубликуй черновик, доставь событие дважды и запроси карточку. После обработки видна опубликованная версия, в поиске осталась одна запись. |

При адаптации замени карточку и каталог своим агрегатом и ограниченным контекстом. Укажи допустимую задержку чтения в единицах времени. Если клиенту нужна актуальная версия сразу после записи, опиши путь чтения, на котором она уже доступна.

Для операций с базой данных уточняй гарантии выбранной СУБД.
